# Software requirements (implemented behaviour)

| ID | Requirement | Where |
|---|---|---|
| FR-1 | JWT auth with refresh rotation; six roles; tenant derived from token | `auth`, guards |
| FR-2 | Product CRUD, search, category filter, pagination; unique SKU per tenant | `products` |
| FR-3 | Image upload via signed URL; validate type/size/decodability; require authorisation confirmation | `media`, `Dropzone` |
| FR-4 | Creative job: 7 styles × 4 ratios × 1–4 variations; provider adapter (generate/edit/getStatus); async via queue; provenance; DRAFT→PENDING_REVIEW→APPROVED/REJECTED; export only if APPROVED | `creatives`, `core/ai/image` |
| FR-5 | Campaigns; only approved assets attach; ACTIVE needs approver role | `campaigns` |
| FR-6 | Public enquiry (all specified fields), unticked consent, Zod validation, rate limit, honeypot/timing/Turnstile, no echo | `public/leads` |
| FR-7 | Contact + lead + opportunity + consent record + assignment + notification + qualification job | `LeadsService.capture` |
| FR-8 | LLM extraction to the specified JSON schema, strict validation, deterministic score (30/20/20/15/15), nulls for unknown, human-review flag | `core/ai/qualification` |
| FR-9 | Kanban (8 stages, drag/drop + keyboard menu), lead list/search/filters, detail, timeline, notes, tasks/reminders, assignment, opportunity values, AI reply ideas, CSV import with preview/duplicate detection, daily dashboard | `leads`, `opportunities`, web |
| FR-10 | Gmail OAuth (least privilege, encrypted refresh token, revocation handling); draft → PENDING_REVIEW → approve (creates Gmail draft) → separate confirmed send; versioned approval; idempotent send; consent/recipient re-check; provider-confirmed message id; CRM activity + audit | `integrations`, `communications` |
| FR-11 | n8n workflows A–E, tenant-aware, HMAC auth, retries, idempotency | `automation`, `automation/n8n` |
| FR-12 | Analytics: overview, leads, campaigns/content production | `analytics` |
| NFR-1 | Standard error envelope, pagination, OpenAPI | api |
| NFR-2 | Structured redacted logging; audit trail | pino, `audit` |
| NFR-3 | Responsive 390–1440 px, keyboard accessible controls, state not conveyed by colour alone | web |
| NFR-4 | Fail-fast configuration; no secrets in code/logs | `core/env` |

Deliberate deviations from the master brief: PostgreSQL tables added (`refresh_tokens`, `lead_notes`, `tasks`, `notifications`); `encrypted_credentials_reference` stores ciphertext rather than a vault pointer; Gmail "Google sign-in" and "Improve draft" buttons from the mock-up were **not** built because they would have been non-functional; ShadCN components are hand-written (Radix + CVA) rather than generated by the CLI.
